# Правила работы над «Хранителем Долины» (для ИИ-агентов)

Этот файл — точка входа для любого агента. Прочти его целиком перед первой правкой.
Документация проекта: `docs/` (см. раздел «Документация» ниже).

## Как работать с гейм-директором

- Общайся с гейм-директором по-русски и объясняй технические решения простыми словами — он новичок в геймдеве.
- Выполняй только текущую согласованную задачу. `docs/roadmap.md` — не разрешение реализовать всё перечисленное.
- Если важное для игрового процесса решение не согласовано — перечисли варианты и попроси выбрать. Для мелочей предложи простой временный вариант и явно обозначь его.
- Не добавляй код, файлы, фичи или инструменты, которых задача не требует. Никаких систем «на будущее».
- Перед правкой механики проверь `docs/decisions.md` — возможно, это уже обсуждалось и решено.

## Жёсткие правила проекта

- Движок: Godot 4.7.2, язык: GDScript. Всё (сцены, UI, визуал) строится кодом — новые .tscn не создаём.
- Графика на этом этапе — цветные примитивы (`_draw`, ColorRect). Спрайты не добавлять без запроса.
- UI и весь текст игры — на русском.
- Не трогать папку `.godot/` и файлы настроек движка без необходимости.
- Файлы `*.gd.uid` коммитим вместе со скриптами (так надо в Godot 4.4+).

## Процесс внесения правок

1. Прочти затронутые файлы целиком, затем правь точечно (Edit, не переписывай файл).
2. Поменял механику или число баланса — в том же коммите обнови `docs/mechanics.md` и/или `docs/balance.md`.
3. Прогони импорт + автотесты + 180 кадров. Красные тесты = правка не сделана, чини.
4. Коммит: `git -c commit.gpgsign=false commit` (GPG-подпись в этом окружении недоступна).
5. Пуш на GitHub (`sl1Bridge/valley-keeper`, ветка `master`) — через GitHub-плагин (`push_files`), затем `git fetch origin && git reset origin/master` для синхронизации.
6. В итоговом сообщении: что изменено, что проверено, что предлагается дальше.

## Типичные грабли (уже наступали)

- Нельзя удалять ноду через `free()` внутри обработчика её собственного сигнала — краш. Только `queue_free()` (см. `GearScreen.rebuild()`).
- GDScript не выводит тип через `:=` из Variant (`max()`, `load()` без каста) — указывай тип явно.
- Вложенный класс: `class Chest:\n\textends Node2D`, не однострочник.
- В headless-тестах узлы вне дерева: всё, что требует `get_tree()` (твины, таймеры), защищай `is_inside_tree()`.

## Если застрял

- Тесты падают второй раз подряд по непонятной причине — остановись и опиши проблему гейм-директору.
- Не уверен, входит ли что-то в задачу, — спроси. Предложить варианты лучше, чем угадать неправильно.
- Не выдавай непроверенное за проверенное: не прогнал headless — так и скажи.
